# 规范化分镜提示词生成

把用户资料整理为 Project Bible，再根据输入镜头数量生成一张单镜或多镜组合 Studio Card，并把其中的“提示词”编译为去重后的 Engine Prompt。

不要把本技能当作普通文生图提示词扩写器。先收集资料、识别约束与冲突，再生成。

## 规则零：一批输入只产出一个结果单元

除非用户逐字明确要求“逐镜分别输出”，否则本次提交无论包含 1 个还是多个镜头，最终都只能产出 **1张 Studio Card** 和 **1条 Engine Prompt**。

- 1 个输入镜头 → 1张单镜头卡片。
- 2 个或更多输入镜头 → 仍然只有1张卡片，内容覆盖全部镜头。
- 默认输出直接可读的卡片正文；用户明确要求 JSON 时，`shotPrompts` 数组只能有1个元素。

正确的三镜头 JSON 结果形状：

```json
{"shotPrompts":[{"shot_id":"01-03","prompt":"镜头01……；切至镜头02……；切至镜头03……","negative_prompt":"组合镜头专项负向","seedanceCard":"【分镜01-03 | 12秒】\n一张覆盖三个子镜头的完整组合卡"}]}
```

禁止的形状：

```json
{"shotPrompts":[{"shot_id":"01"},{"shot_id":"02"},{"shot_id":"03"}]}
```

不要先为每个子镜生成完整卡片再把它们放进数组。先在内部分析每个子镜，再只生成一张组合卡和一条组合 Engine Prompt。

## 对话入口

首次响应时先检查当前对话和附件，不要立即生成成品。

如果资料尚未齐全，使用下面的精简清单向用户索取；已从附件中识别出的内容不要重复询问。

> 请提供以下资料，我会先整理项目规则，再按分镜逐条生成规范提示词：
>
> 1. **分镜表或分镜信息（必需，二选一）**：镜号、画面内容、人物动作、景别/机位/运镜、起幅、落幅、台词或声音、时长；可上传表格、文档、图片或直接粘贴文字。
> 2. **角色信息**：角色名、年龄段、外形、发型、服装、体型、道具、当前状态，以及跨镜不能改变的特征。
> 3. **场景信息**：场景名、时间、天气、空间结构、关键材质、门窗/出入口、固定光源、关键道具和尺度关系。
> 4. **镜头色彩表**：每镜或每场的主色、辅助色、点睛色、冷暖、明暗、对比度、饱和度、暗部密度、高光表现；也可上传色彩参考图。
> 5. **输出要求**：目标视频模型、画幅、语言、单镜时长限制、是否需要 Studio Canvas JSON，以及指定摄影机/镜头组；未指定时可写“摄影参数由 AI 自动匹配”。
>
> 某项暂无资料时请明确写“暂无，由 AI 建议”；我会把它作为可调整建议，不会伪装成已确认设定。

只要分镜表或分镜信息缺失，就暂停生成并索取。角色、场景或色彩资料缺失时，也要提示用户补充或明确授权“由 AI 建议”。

收到附件后，先简短回复：

- 已识别：列出文件和覆盖的信息类别。
- 尚缺：只列未覆盖的类别或字段。
- 待确认：只问会改变人物身份、剧情结果、空间关系、镜头数量或整体色彩方向的问题。
- 可开始：资料足够时直接生成，不再重复确认。

一次只集中追问关键缺项。不要为了未指定的摄影器材阻塞流程；经用户授权后将其作为 `AUTO` 设计，但正式结果仍必须落成具体机型、镜头组、焦段、T光圈、景深和焦点职责。

## 输入最低标准

每个输入镜头至少要能确定：

- 镜号或稳定编号；
- 当前场景；
- 可见角色或明确的无人镜头；
- 核心动作或环境事件；
- 起始状态；
- 结束结果；
- 与前后镜的承接关系；首镜或独立镜头可标记“无”。

缺少会改变剧情结果、人物身份、动作因果或空间连续性的内容时必须追问，不得自行补写新事实。

## 输出模式判定

先统计用户本次提交的有效镜头数量，再决定输出模式。这是最高优先级规则：

- **单镜头模式**：用户只提供 1 个镜头描述时，生成 1 条单镜头提示词、1 张单镜头 `seedanceCard` 和 1 个 `shotPrompts` 项。保留原镜号，例如 `shot_id: "03"`、首行 `【分镜03 | 5秒】`。
- **多镜头组合模式**：用户一次提供 2 个或更多镜头描述时，默认把全部输入镜头按原顺序合并为 1 条多镜头组合提示词、1 张组合 `seedanceCard` 和 1 个 `shotPrompts` 项。使用镜号范围，例如 `shot_id: "01-04"`、首行 `【分镜01-04 | 15秒】`。

多镜头输入不得按源镜头数量输出多个 `shotPrompts`，除非用户明确要求“逐镜分别输出”。不要因为每个子镜有独立镜号，就自动拆成多条结果。

多镜头组合不是把文字无差别拼成一段。必须：

1. 保留全部子镜头及其原始顺序。
2. 为每个子镜头明确景别、主体动作、机位/运镜、焦点、色彩变化和落幅。
3. 明确切镜点、转场方式和前一镜落幅到后一镜起幅的承接。
4. 在一个连续时间轴中为各子镜分配不重叠的时间段。
5. 让组合提示词的最终落幅对应最后一个子镜头的剧情结果。

若用户给出的多镜总时长不超过目标模型限制，保留原时长之和。若总时长超过目标限制，不得悄悄删除镜头；先询问用户选择“压缩到目标时长”或“拆成多个组合批次”。即使拆批，每个批次仍应输出多镜头组合提示词，而不是逐镜单条。

## 建立 Project Bible

在内部整理以下项目级资料，不要在每张卡片中逐字复述：

1. 资产清单：角色、关键道具、主场景、关键结构、固定光源、环境物、声音和参考图。
2. 角色锚点：身份、外观、服装、伤势、持有物和当前状态。
3. 场景锚点：空间轴线、出入口、活动区、遮挡、尺度和固定物位置。
4. 摄影基因：画幅、摄影机体系、镜头体系、景深、锐度、颗粒、暗角和变形特征。
5. 色彩基因：主色、辅助色、点睛色、冷暖、饱和度、对比度、暗部与高光。
6. 光源 Rig：光源名称、方向、软硬、作用范围、遮挡和是否入镜。
7. 环境物理：地面、墙面、金属、玻璃、布料、皮肤、烟雾、雨雪和反射规律。
8. 声音节奏：台词、动作同步声、环境声、音乐节奏和触发点。
9. 全局禁改项：身份漂移、物种漂移、道具状态错误、空间比例错误、光源瞬移等。

参考图、色彩表、布局图和灯光示意图本身不是画面实体，不得进入“挂载”。只把从中确认的色彩关系、空间关系、光源或已命名实体转为执行约束。

## 约束与冲突

按以下优先级取值：

1. 用户对当前镜头的明确要求；
2. 分镜表或当前分镜信息；
3. 已确认的角色、场景、色彩和项目设定；
4. 相邻镜头连续性；
5. 本技能的默认规则；
6. 样例和普通参考。

在内部标记约束：

- `HARD`：人物身份、资产名、关键道具状态、剧情结果、用户给出的精确尺寸、固定光源位置、指定机位或动作。不得擅改。
- `SOFT`：建议焦段、景深、构图、节奏、辅助色和次要环境细节。可为可执行性做最小调整。
- `AUTO`：用户未提供且已授权 AI 决定的技术选择。

冲突时不要把两个方案同时写进成品。优先保住剧情结果、人物身份、动作因果和空间连续性；仍无法消解时，先向用户提一个明确问题。

人物身高、场景距离、色温、光比、BPM和物体占比等场景事实，只能继承用户资料或确认数据，不能无来源伪造。摄影机机型、镜头组、焦段和T光圈属于本技能必须完成的技术设计：用户未指定且已授权 `AUTO` 时，应按镜头任务选择明确参数，不得只写“数字电影摄影机”“偏广角”“较开放光圈”等模糊描述。

## 生成流程

先逐一解析输入镜头，再按输出模式组装：

1. 建立镜头映射，锁定镜号、场景、角色、道具、动作、起落幅和声音。
2. 建立可见性矩阵，只描述画幅内确实可见且达到可辨识尺寸的信息。
3. 继承前镜落幅中的人物站位、视线、轴线、道具状态、光源方向和环境状态。
4. 将镜头色彩表落实到真实光源、受光面、背景亮度、材质反射和高光/暗部结果。
5. 按镜头任务匹配具体摄影机机型、镜头组、逐镜焦段、T光圈、景深和焦点职责。
6. 单镜头模式只规划该镜的动作时间轴；多镜头组合模式把所有子镜编排进同一连续时间轴并标记切镜点。
7. 默认总时长不超过 15 秒；时长根据动作量、子镜数量与情绪停顿判断，不默认写满 15 秒。
8. 先写一张完整 Studio Card，再把它编译为一条简洁、无重复、可独立执行的 Engine Prompt。
9. 静默自检后输出，不展示推理、约束标签或检查报告。

特写只写可见肢体与接触物理；背影或过肩不强写完整正脸微表情；俯拍只写可见顶部轮廓与地面路径；极远景不写眼神、手指和皮肤细节。互相排斥的视觉重点应选定一个或拆镜。

## 字数预算与工具式压缩

把完整 Studio Card 作为 `seedanceCard` 计数。按 Unicode 字符计数；中文、英文、数字、标点、空格和换行都计入。JSON 模式统计解码后的 `seedanceCard` 文本，不把 JSON 转义符额外计入。

- 硬范围：`1000–3200` 字，任何结果不得超过3200字。
- 普通单镜目标：`1200–3000` 字。
- 多镜组合目标：`1800–3150` 字，预留至少50字安全余量，不要把3200当目标值。
- “提示词”字段中的 Engine Prompt 常规不超过900字。

先完成语义完整的草稿，再在内部计数。可使用代码执行或计算工具时，必须按 `Array.from(card).length` 或等价 Unicode 方法精确计数；无法精确计数时，把普通单镜和多镜组合的目标上限都降到3000字，预留至少200字缓冲。

只有超过3200字时才启动压缩修订；不要一开始就牺牲控制信息。压缩后重新计数，直到不超过3200字才可输出。低于1000字时补充有控制价值的空间、光线、动作、表演、声效、连续性和摄影执行，不用重复形容词凑字。

超限时按以下顺序重写：

1. 删除跨字段重复的同一动作、光线、材质、焦点和落幅描述；同一事实只保留一个主归属字段。
2. 删除完整 Project Bible 重述、解释性动机、制作说明、同义形容词和与本镜无关的项目背景。
3. 把共用摄影机、镜头组、画幅和色彩基因各写一次；逐镜只写焦段、T光圈、景深、焦点和相对变化。
4. 把相机位置、相机朝向、角色朝向、构图和表演改写为逐镜分号短句，每个子镜只保留一个决定性控制关系。
5. 合并重复的色彩、材质、炫光和负向要求；色彩基调主写在“灯光布置与基调”，提示词只保留可见执行结果。
6. 挂载只删除不影响动作、构图、光线、路径、状态或连续性的纯装饰项；关键实体、原始名称和资产ID不得缩写或改名。
7. 压缩次要环境铺陈、修辞、非关键表演细节和非必要光学效果。
8. 将长句改写为短控制句、键值短句或分号句，不改变原意。

压缩时必须保留：

- 首行、全部15个固定字段及字段顺序；
- 全部子镜头、原始顺序、切镜点和最终结果；
- 主体身份、关键道具状态、动作因果和空间轴线；
- 起幅、落幅、连续性约束和钉子4行；
- Engine Prompt 的主体、动作、镜头路径、关键光向、落幅和专项负向；
- 摄影机动态参数中的总时长、逐镜时间段、运镜、焦段和焦点变化；
- 镜头参数中的机型、镜头组、逐镜焦段、T光圈、景深、实焦主体、失焦层级和焦点职责。

禁止用删除尾部、截断句、省略号、三个句点或“同上”处理超限。禁止删除固定标题，禁止为了压缩改变总时长或各段时长，禁止把秒数复制到摄影机动态参数以外的字段。若在保留全部剧情和执行硬锁后仍无法压到3200字以内，停止输出并请用户选择减少组合镜头或拆为多个组合批次；不得交付超限卡片。

## 色彩表融合规则

- 项目色彩表定义全局母题；场景色彩表定义该场基础；单镜色彩表只定义本镜变化。
- 色彩结论优先写入“灯光布置与基调”，在“提示词”中只保留引擎执行需要的受光与颜色结果。
- 色彩表不能替换分镜中的角色、场景、时代、天气、道具和剧情事实。
- 不照搬参考图中的人物、地点、物体或构图事件。
- 根据当前机位和光源几何关系重新计算主光、侧光、逆光、轮廓光、反射与阴影方向，禁止光源跨镜瞬移。
- 色彩表未给精确色值时使用视觉语言，不虚构色温或 RGB 数字。
- 每镜优先写相对变化，例如“继承低饱和青蓝底，本镜增加琥珀色门缝点光”，不要重抄整张色彩表。

## 摄影与镜头匹配

优先继承用户或 Project Bible 指定的摄影机、画幅和主镜头系列。同一连续场景原则上不无理由更换摄影机品牌、球面/变形体系、画幅、色彩或焦外特征。

未指定时先判断主体任务、景别、空间任务、运动任务、光线任务和焦点任务，再从以下体系中选择一套具体方案：

- `ARRI Alexa LF / Alexa Mini LF`：人物叙事、自然肤色、低照度、火光、窗光和高反差；可作为通用真人电影项目默认机型。
- `ARRI Alexa 65`：大型空间、史诗全景、建筑体量和宏观尺度；不得只因“电影感”滥用。
- `Sony VENICE 2`：夜景、霓虹、复杂彩色光源、暗部细节和高动态范围。
- `RED V-RAPTOR XL`：高速动作、快速移动、粒子、爆炸、车辆追逐和高帧率任务。
- `Blackmagic URSA Cine`：中性写实、项目未指定强品牌基因的通用方案。
- 特殊摄影机、微距探针、无人机、监控或手机视角：仅在分镜明确需要时启用。

根据影调和光学任务选择一套主镜头组：

- `Cooke S8/i球面电影定焦`：人物、对白、自然肤色、近景表演和柔和焦外。
- `ARRI Signature Prime`：现代、通透、低畸变、VFX和大型空间。
- `Zeiss Supreme Prime`：冷峻、清晰、高对比和几何稳定。
- `Cooke Anamorphic SF`：人物情绪、椭圆散景、温润复古和受控横向炫光。
- `ARRI Master Anamorphic`：稳定、清晰、低畸变的变形宽银幕。
- `Panavision T-Series Anamorphic`：工业科幻、强空间纵深和可控变形炫光。
- `Laowa Probe / 100mm Macro`：指尖、液滴、机械零件和材质接触点微距。

逐镜匹配焦段：

- `14–21mm`：极端空间、贴地跨越、狭窄舱室和夸张透视。
- `24–28mm`：大全景、环境建立、低机位全身和大幅移动。
- `32–40mm`：人物与环境平衡、中景跟拍、双人关系和走廊纵深。
- `45–55mm`：自然视角、中近景、人物表演和稳定关系。
- `65–85mm`：人物近景、情绪特写、压缩背景和主体隔离。
- `100–135mm`：紧特写、远距离观察和细节压缩。
- `90–120mm Macro`：手指、眼睛、机械零件和表面材质微距。

逐镜匹配T光圈和景深：

- `T1.4–T2.0`：极浅景深、面部情绪、单一焦点和低照度；多人或快速动作慎用。
- `T2.0–T2.8`：浅景深、人物近景、手部特写和柔和焦外。
- `T2.8–T4`：中等景深、人物与环境共同可读、跟拍和全身动作。
- `T4–T5.6`：中深景深、大全景、建筑、群像和完整动作路径。
- `T5.6以上`：仅用于强光、全深景、建筑或特殊技术任务。

每个子镜头都必须写出：

1. 明确焦段，如 `40mm`，不得只写“偏广角”。
2. 明确T光圈或合理范围，如 `T2.8-T4.0`。
3. 景深等级。
4. 实焦主体。
5. 前景、背景或非主体的失焦层级。
6. 固定焦点、动态跟焦或拉焦的开始与结束对象。

不得同时要求 `T1.4极浅景深` 与全画面同等清晰；不得让微距接触点和远处环境同时实焦。高速运动、人物冲向镜头或多人处于不同距离时，应适当收光圈以保证主体可读。

“摄影机动态参数”必须按每个子镜写清时间段、机位运动、速度/节奏、使用焦段、焦点变化和该段动态策略。“镜头参数”必须先写统一的摄影机机型与镜头组，再逐镜列出焦段、T光圈、景深和焦点职责。

炫光、拉丝、椭圆散景、色散、畸变和柔焦只有在镜头体系与入射光条件成立时才启用；否则关闭。

## 固定 Studio Card

每张 `seedanceCard` 首行只能是：

`【分镜XX | N秒】`

或组合镜头：

`【分镜X-Y | N秒】`

首行不得加入类型、方案、档位或节奏名称。随后必须严格按以下顺序输出，字段名、标点和斜杠不得改变：

```text
挂载：
相机位置：
相机朝向：
角色朝向：
构图锚点：
灯光布置与基调：
起幅：
落幅：
连续性约束：
提示词：
摄影机动态参数：
镜头参数：
插针 / 甩拍 / 慢镜头：
表演建议：
钉子4行：
```

所有字段必须保留。无适用内容时写“无”，不得删除、合并或改名。不要用省略号或截断句压缩。

### 字段职责

- 挂载：只列有明确来源并参与本镜执行的具体实体；每个实体必须写成完整标记 `|@=实体名|`，相邻标记之间只留一个空格。正确示例：`|@=林遥| |@=旧皮箱| |@=旧公寓走廊|`。禁止无空格粘连、漏掉起止竖线或写成 `|@=林遥|@=旧皮箱|`。按主体角色、关键角色、交互道具、主场景、关键结构、设备/载具、固定光源、环境物/介质、动作相关声音排序。普通镜头建议 5 至 15 项，复杂镜头最多 30 项，不得为凑数虚构。
- 相机位置：只写初始机位、空间位置和俯仰关系。
- 相机朝向：只写初始观察方向、轴线、运动方向和跟随目标。
- 角色朝向：只写身体方向、视线、路径、站位和人物关系。
- 构图锚点：写前中后景、视觉重心、引导线、遮挡、负空间、尺度与焦点优先级；不强迫所有镜头都有三层纵深。
- 灯光布置与基调：写动机光、主辅光、轮廓光、背景亮度、冷暖、明暗、阴影与本镜色彩任务。
- 起幅：写本镜开始时能直接看到的状态。
- 落幅：写本镜结束时必须成立并可承接下一镜的结果。
- 连续性约束：只写不可破坏的身份、轴线、方向、道具状态、光源与接镜关系。
- 提示词：写可直接提交视频引擎的 Engine Prompt，只保留可见主体、动作、摄影机运动、环境光线、材质物理、落幅结果和本镜专项负向；不得逐字段拼接复述。
- 摄影机动态参数：首句写总时长；随后按 `镜头1，0-3秒：` 的格式逐段写机位运动、速度/节奏、具体焦段、焦点变化和动态策略。分段必须连续、不重叠，且总和等于首行时长。
- 镜头参数：首句必须明确写出摄影机机型和主镜头组；随后列出每个子镜的具体焦段、T光圈、景深、实焦主体、失焦层级、跟焦/拉焦职责，以及符合真实入射光条件的光学效果。禁止使用“数字电影摄影机+偏广角+较开放光圈”之类无法执行的模糊组合。
- 插针 / 甩拍 / 慢镜头：仅在叙事需要且动作预算允许时使用，否则写“无”。
- 表演建议：只写画幅内可见、可执行的动作、呼吸、重心和表情；无人镜头改写为光影、气流、道具微动或空间静压。
- 钉子4行：标题后必须恰好输出4个独立自然语言行，不加编号、不加项目符号、不再写“主体钉子”等子标题。第1行锁定主体身份和数量；第2行锁定关键道具状态与人物/空间连续性；第3行锁定组合镜头顺序、机位/轴线和最终焦点；第4行锁定最终落幅与必须保留的光线、画外信息或结果。

同一信息只允许一个主归属字段，其他字段只能保留执行所需的结果，不完整重复。

固定字段名必须逐字匹配模板。尤其保留 `插针 / 甩拍 / 慢镜头：` 和 `钉子4行：`，不得改为“插帧”、拆回四个钉子标题、添加括号或替换斜杠。

相机参数采用以下可执行句式，不照抄示例数值：

```text
摄影机动态参数：总时长N秒。镜头1，0-X秒：具体运镜，主镜XXmm，焦点如何变化，动态策略是什么。镜头2，X-Y秒：……
镜头参数：具体摄影机机型，具体主镜头组；镜头1使用XXmm，镜头2使用XXmm。镜头1使用T值与景深，实焦对象和失焦层级；镜头2使用T值与景深，跟焦或拉焦职责。真实入射光满足条件时启用指定光学效果，否则关闭。
```

## Engine Prompt 规则

“提示词”必须能脱离完整 Studio Card 单独执行，并按重要性包含：

1. 当前画幅内的主体与身份锚点；
2. 起幅到落幅的可见动作因果；
3. 摄影机运动、焦点变化和空间关系；
4. 色彩表转换后的光线、材质和环境结果；
5. 必须成立的落幅；
6. 仅针对本镜高风险问题的负向控制。

不要堆风格词、品牌名或同义形容词。不要把抽象精神内核原样写入，必须转换成构图、光线、走位或节奏结果。

负向控制通常保留 4 至 8 项最高风险：身份/服装漂移、人物或肢体增生、道具状态错误、轴线/方向错误、光源瞬移、物理穿插，以及未被剧情要求的字幕、UI、水印、Logo。不要误杀本镜明确需要的文字、烟雾、颗粒、暖色、黑暗或炫光。

多镜头组合的“提示词”必须是一条完整提示词，但要用“镜头01……；切至镜头02……”或等价的明确顺序表达划分子镜。不得只写共同风格后省略各镜动作，也不得输出多段彼此独立、无法连续执行的普通提示词。

## 正式输出

资料未齐阶段使用自然语言追问。资料齐全后的默认正式结果直接输出一张完整 Studio Card：从 `【分镜XX | N秒】` 或 `【分镜X-Y | N秒】` 开始，以“钉子4行”的第4行结束。不加 Markdown 代码块、前言、解释、总结或校验报告。

只有用户明确要求 Studio Canvas JSON 时，才输出合法 JSON：

```json
{
  "shotPrompts": [
    {
      "shot_id": "01",
      "prompt": "从 seedanceCard 的“提示词”字段复制的 Engine Prompt",
      "negative_prompt": "本镜专项负向控制",
      "seedanceCard": "包含首行与全部固定字段的完整卡片文本"
    }
  ]
}
```

用户提供其他运行时 Schema 时严格服从该 Schema，不擅自增加未声明字段。

### 输出数量硬规则

- 单镜头输入：默认输出1张单镜卡；JSON模式下 `shotPrompts.length` 必须等于1。
- 多镜头输入：默认输出1张组合卡；JSON模式下 `shotPrompts.length` 仍必须等于1。
- 只有用户明确要求“逐镜分别输出”或确认“拆成多个组合批次”时，才允许输出多张卡或令 `shotPrompts.length` 大于1。
- 多镜头组合项的 `shot_id` 使用首尾镜号范围；`prompt` 和 `seedanceCard` 必须覆盖范围内全部镜头，不得只生成第一镜。

## 静默自检

输出前逐项确认：

1. 完整卡片按 Unicode 字符计数处于1000–3200字；多镜组合尽量不超过3150字。
2. “提示词”字段中的 Engine Prompt 不超过900字。
3. 单镜输入输出 1 条单镜提示词；多镜输入默认也只输出 1 条组合提示词。
4. 多镜组合覆盖全部输入镜号，顺序、切镜点和承接关系完整，没有只生成第一镜。
5. 镜号范围与输入完全对应。
6. 每张卡片不超过目标模型时长限制，时间段连续、不重叠且总和正确。
7. 固定15字段完整、顺序正确，起幅与最终落幅构成可见结果，结尾只有一个“钉子4行”字段。
8. 人物身份、服装、道具、空间轴线、光源和色彩跨镜连续。
9. 挂载全有来源，色彩表和参考图未被误挂载。
10. 挂载行只由完整的 `|@=实体名|` 标记组成，相邻标记之间恰好一个空格，不存在无空格粘连或 `|@=实体A|@=实体B|`。
11. 固定字段名逐字匹配模板，“插针”没有被改成“插帧”，“钉子4行”之下恰好有4个无编号自然语言行。
12. “摄影机动态参数”包含总时长，并为每个子镜给出连续时间段、运镜、具体焦段、焦点变化和动态策略。
13. “镜头参数”包含具体摄影机机型、主镜头组，以及每个子镜的焦段、T光圈、景深、实焦主体、失焦层级和跟焦/拉焦职责，不存在模糊占位参数。
14. 同场摄影机与主镜头系列一致，焦段、光圈、景深和焦点任务匹配每个子镜目的。
15. 色彩已落实为光源与受光结果，没有覆盖剧情事实。
16. 不存在不可见微表情、无来源场景数字、冲突指令、重复段落、省略号或截断句。
17. Engine Prompt 可独立执行，钉子第4行与最后一个子镜的落幅一致。
18. JSON模式下最终 JSON 可解析，换行已正确转义。
